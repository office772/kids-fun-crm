## 4. תוכנית בנייה — 4 פאזות, מהבטוח לגדול

> עיקרון-על: **כל ערך נקרא מ-DB עם fallback לערך הקשיח הנוכחי.** אף פאזה לא מסירה fallback. כל שינוי לבוט → `replay-bot.ts` + טסט חדש + tsc, ואז deploy נקודתי.

### פאזה 1 — קול הבוט בהגדרות (הכי בטוח, ~4-6ש')
- טבלה: להשתמש ב-`settings` הקיים (key/value) עם מפתחות: `bot_persona_name`, `bot_gender` (`male`/`female`/`neutral`), `bot_formality`, `bot_emoji_level`, `bot_greeting`, `bot_signoff`, `bot_phrases_use` (CSV/JSON), `bot_phrases_avoid`, `bot_forbidden_words` (למשל "בוט"), `bot_sample_answers` (2-3 few-shot).
- API: `src/app/api/admin/settings/route.ts` — GET כל ה-settings, PATCH upsert (לחקות `test-phones` route). **זה ה-route החסר שכל שאר הפאזות צריכות.**
- מסך: מקטע "🗣️ קול הבוט" **בלשונית הגדרות** (בתוך `SystemSettings.tsx` או קומפוננטה נפרדת תחת אותה sub-tab). שדות עם שמירה אמיתית + הודעת "נשמר" אמיתית.
- חיווט ל-LLM: ב-`src/lib/bot/llm-fallback.ts` — לטעון את מפתחות הקול פעם אחת ולהזריק ל-system prompt (persona, מגדר, few-shot). **אם ריק → הפרומפט הנוכחי בלי שינוי** (כך לא נוגעים בטון עד שהלקוח ממלא). אותו דבר ב-`media-handler.ts`.
- מגדר בטקסטים קבועים: helper `gendered(masc, fem, neutral)` לפי `bot_gender`, להחיל על ~5 מקומות בלשון נקבה (`flows.ts:1860,1941`, `media-handler.ts` fallback, `llm-fallback.ts` נציגה) — לא re-write גורף.

### פאזה 2 — הגדרות מערכת עריכות + הבוט קורא מהן (~6-9ש')
- להסיר את הבאנר מ-`SystemSettings.tsx` ולחבר לשמירה אמיתית (GET/PATCH `/api/admin/settings`).
- שדות אמיתיים: שעות פעילות (start/end/days), מחיר ברירת מחדל, טוגלים (רישום פתוח וכו'), מקס' רשימת המתנה. **להסיר שדות מזויפים/סודות** (PayPlus API key וכו' — לא לחשוף בדשבורד).
- הבוט קורא: לרכז טעינת settings **פעם אחת לכל בקשה** ב-webhook (`route.ts`) ולהעביר ב-context (לא async בתוך כל תבנית). לשנות `isBusinessHours()` לקבל שעות מה-settings (עם fallback `8/17/[0-4]`). מחיר ברירת מחדל 799 → מ-settings.
- ⚠️ זה משנה התנהגות באוויר → deploy זהיר, לוודא replay עדיין ירוק עם ברירות המחדל.

### פאזה 3 — הוספה/הורדה של מסגרות (~3-5ש')
- CRUD מלא ל-`schools` (add/edit/deactivate) — להרחיב `CapacityManager`/`schools` API או מסך "ניהול מסגרות". שדות: שם, אזור, מחיר חודשי, קיבולת, פעיל.
- לחבר את `resolveMonthlyFee` לקרוא מחיר מ-`schools.monthly_price` (עם fallback ל-`pricing.ts`).
- לעדכן את ה-fallback הקשיח `registration-helpers.ts:21` שלא יתנגש.

### פאזה 4 — עריכת טקסט ההודעות הקבועות (הגדול, ~10-15ש', אחרון)
- טבלה חדשה `bot_messages` (key ייחודי, text, is_active). למפות את ~150 ההודעות ב-`flows.ts` למפתחות (למשל `register_area_prompt`).
- ב-`flows.ts`: פונקציה `msg(key, fallback)` שמושכת מ-DB (cache לכל בקשה) עם fallback לטקסט הנוכחי. **לא לשבור את המשתנים** — הטקסט מכיל `{...}`; ה-UI חייב לנעול/לוודא שכל ה-placeholders המקוריים נשמרים בשמירה (validation: אם המשתמש מחק/שינה `{...}` → לדחות).
- מסך "תכני הודעות": להחליף DEMO בנתוני אמת מה-DB, עריכת **טקסט בלבד**, המשתנים מוצגים כתגיות נעולות. להסיר את הבאנר.
- **QC כבד:** כל שינוי → `replay-bot.ts` ירוק (הבדיקות בודקות מסלול, לא טקסט, אבל לוודא שאין רגרסיה) + מעבר ידני על מסלול או שניים.
