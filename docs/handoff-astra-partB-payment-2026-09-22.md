## מה השתנה (#7 §10-11)

**היום:** בקשת תשלום → תפריט 6 שיטות מיד (`payset_intro_menu`), ההורה בוחר 1-6.

**עכשיו (§10-11):** מציעים *הוראת קבע ישירות* כאופציה הראשית; חלופות רק **אחרי סירוב**.

שינוי **additive** — לא נגעתי במנגנון בחירת השיטות הקיים (`payment_setup_method`, כולל זיהוי השלילה של R6).

### הזרימה החדשה
1. `payment_setup_start` → הודעת הצעה `payset_offer_standing` → `nextFlow: payment_setup_offer`.
2. `payment_setup_offer` ([flows.ts](../src/lib/bot/flows.ts)):
   - `unambiguousMatch(msg, CONFIRM_STANDING)` (כן / הוראת קבע / מאשר / להסדיר) → `payment_method='standing_order'` → זיהוי שם → לינק (המנגנון הקיים).
   - `isRealQuestion(msg)` → `useLLM` (המסלול נשמר).
   - כל השאר (סירוב / "אפשרות אחרת" / שיטה אחרת) → תפריט החלופות (`payset_intro_menu`) → `payment_setup_method` הקיים.
3. handler: `payment_setup_offer` נוסף ל-`CHOICE_STEPS` ו-`STEP_OWN_INTENTS` (כדי שלא ייחטף ע"י כוונת-תשלום).

### הודעה ניתנת לעריכה (דרישת הלקוחה)
ההודעה החדשה `payset_offer_standing` ב-`BOT_MESSAGE_REGISTRY` → מופיעה **בעורך ההודעות בדשבורד** (`listEditableMessages`), עם **משתנים נעולים** `{פתיחה}` `{סכום}` (ה-PATCH דוחה טקסט שמשנה/מוחק משתנה — `placeholdersMatch`). **אומת חי** בדשבורד: ההודעה מוצגת תחת "הסדרת תשלום" עם המשתנים הנעולים וכפתור שמירה.
> הערה: הלקוח יערוך את נוסחי ההודעות בעצמו (vibe של "ג'וני"). לכן **לא** נגעתי בלשון/מגדר — רק הוספתי את שלב ההצעה. הפרסונה (ג'וני) אושרה על ידי הלקוח אבל עריכת הטונים היא שלו.

## נקודות לאתגור (astra)
1. **`CONFIRM_STANDING`** = `['כן','כן בבקשה','כן להסדיר','להסדיר','הוראת קבע','כן הוראת קבע','קבע','מאשר','מאשרת','אישור']`. האם ניסוח אישור סביר נופל בטעות ל"חלופות"? (כרגע: לא-אישור-ולא-שאלה → תפריט חלופות, שזו התנהגות בטוחה — ההורה רואה אפשרויות.)
2. **תפריט החלופות אחרי סירוב** = `payset_intro_menu` הקיים (עדיין כולל את הו"ק כאופציה 2). בחרתי לשמר את התפריט הקיים (מספור זהה, ללא שינוי ב-parser) לשמירת יציבות, במקום ליצור תפריט חדש עם מיפוי-ספרות אחר. סביר, או שצריך להסיר את הו"ק מהתפריט הזה?
3. **נקיבת שיטה אחרת בהצעה** ("אשראי" בתגובה להצעה): כרגע מוצג התפריט וההורה בוחר שוב (לא ניתוב ישיר) — פשוט ובטוח. מקובל?
