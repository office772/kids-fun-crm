# הנדאוף לסקירת astra - "בוט חכם ואנושי" בלבד (23.9.2026)

**היקף הסקירה המבוקש:** אך ורק השאלה "האם הבוט חכם ואנושי" לפי העיקרון למטה. לא בטיחות כספית, לא מקביליות, לא מסלול התשלום (נסגרו בסבבים 1-14). WhatsApp דרך uChat בלבד.
**קומיטים:** `4a64cf0` → `55ee999` → `0d2ca67` → `faf130f` על `main` (= `claude/kids-fun-astra-review-0ef589`). **פרוס בפרודקשן: webhook 2.4.1.** בסיס להשוואה: `ffb9d7e` (2.3.1).

## העיקרון (עינת, 23.9)
המסלול המהיר עונה קודם. כשההורה סוטה ולמסלול המהיר אין מענה, ה-LLM (Sonnet) חייב לתפוס את מקומו. אחרי הבהרה אחת וניסיון LLM אחד שלא עבדו, מעבירים לקורלי, לא משאירים הורה מתוסכל. אחרי ההפניה, אם ההורה ממשיך, הבוט רשאי לנסות שוב, אבל אם ההורה מבקש נציגה במפורש, הבוט מאשר שהפנייה אצל קורלי. הכרעות כספיות נשארות דטרמיניסטיות בכל שלב. תפריט הפתיחה רק בפתיחת שיחה או כשמבקשים "תפריט".

## מה הופעל (הרקע: "יופי תודה" אחרי שיחה שהסתיימה החזיר תפריט; 12 שלבים חזרו על "לא הבנתי" בלי גבול)

### 1. סולם אחיד באמצע מסלול (`handler.ts` → `processMessageCore`, בלוק המסלול הפעיל)
`BotResponse.notUnderstood` מסומן בכל אתר שמחזיר הבהרת-שלב בלי התקדמות (16 אתרים: 12 שלבי איסוף/בחירה + 4 שלבי אישור). מונה `__miss` פר-שלב ב-`collectedData`:
| תקיעות ברצף | תגובה |
|---|---|
| 1 | הבהרת השלב (המסלול המהיר, כמו קודם) |
| 2 | LLM עם הקשר, המסלול נשמר, תזכורת לשאלה הפתוחה כשיש (`FLOW_REMINDERS`) |
| 3 | "אני מעביר לקורלי" + פנייה (`createTask`), `handoff_paused` |
- התקדמות אמיתית מאפסת את המונה. שלבים שכבר עברו ל-LLM בפעם הראשונה (`useLLM`) נספרים גם הם: LLM, LLM, קורלי.
- **שאלה אמיתית** (`isLikelyQuestion`: סימן שאלה או מילת שאלה) באמצע כל שלב → LLM עם הקשר, **המונה לא זז**. 3 שאלות לגיטימיות לא מעבירות לקורלי. כשל LLM חוזר נתפס ע"י שומר התסכול הקיים (2 תשובות-שגיאה).
- **שלבי אישור כספי** (ביטול ×2, מקום ברשימת המתנה, אישור ילד בכשל תשלום): שאלה → LLM; היסוס ("כן אבל רגע", "אולי") → שאלת האישור מחדש (פעם 1), LLM + תזכורת "כן / לא" (פעם 2), קורלי (פעם 3). **הפעולה הכספית מתבצעת רק ב"כן" מפורש מהרשימה הסגורה, ללא שינוי.** ה-LLM לא מכריע.

### 2. רגעים אנושיים בלי מסלול פעיל (`processMessageCore`, לפני FAQ וכוונה)
- **תודה** (`isThanksClosing`): הודעה עד 7 מילים עם "תודה", בלי סימן שאלה, בלי מילת שאלה/ניגוד/בקשה (`THANKS_BLOCKERS`), והמסווג לא זיהה כוונה ממשית → `thanks_reply` ("בשמחה! אם צריך עוד משהו אני כאן 💛"). "תודה, אני רוצה לבטל" → מסלול ביטול. "תודה אבל לא הבנתי מתי מחייבים" → LLM.
- **פרידה** (`isFarewell`): אוצר סגור עם עוגן חובה (לילה/ביי/להתראות/שבת/חג/שנה/סופש/שבוע/בהצלחה) + ביטויים שלמים ("יום טוב", "יום נעים") → `farewell_reply` חדש ("תודה, וגם לכם 😊 אני כאן בכל שאלה 💛"). "לילה טוב" קודם החזיר תפריט.
- **פתיחה מוכרת** (`isShortGreeting`, עד 3 מילים עם מילת פתיחה: שלום/היי/הלו/אהלן/בוקר/ערב/צהריים) → תפריט. "תודה"/"לילה" הוצאו מרשימת הפתיחה.
- **פתיחה לא מוכרת בהודעה ראשונה** (עד 3 מילים, לא שאלה, אין היסטוריה) → LLM לפי ההקשר **ואז** התפריט. שאלה אמיתית בהודעה ראשונה → LLM בלי תפריט.
- **תגובות קצרות באמצע שיחה** ("יופי", "מעולה", "אוקיי", "הבנתי") → LLM עם ההיסטוריה, בלי תפריט.
- שלושת הכללים האלה הוצאו מתוך `case 'שאלה_כללית'` (שם הם רצו רק כשהמסווג החזיר את הכוונה הזו) לבדיקה מרכזית.

### 3. אחרי הפניה לקורלי (`processMessage`, בלוק `HANDOFF_FLOW`)
| ההורה כותב | תגובה |
|---|---|
| בקשה מפורשת לנציגה/מענה אנושי (`classifyIntent` = בקשת_נציג) | `handoff_still_open` ("הפנייה שלך כבר אצל קורלי, היא תחזור אלייך בהקדם 💛"), בלי LLM |
| שאלה אחרת, פעם ראשונה | LLM (הקשר: "השיחה הועברה לקורלי, ענה קצר וחם, בלי תהליך") + `handoff_llm_note` ("בכל מקרה קורלי תחזור אלייך") |
| שאלה נוספת | שתיקה (כמו קודם) עד שקורלי מחזירה את הבוט |
| ג'יבריש/אמוג'י | שתיקה |
| "תפריט" / ספרה | יציאה מההפניה (ללא שינוי) |
- **מגבלה ידועה:** אין לנו אות כשקורלי עונה בעצמה ב-Live Chat. לכן ניסיון LLM אחד בלבד ואז שתיקה. Edry Connect פותר את זה עם webhook להודעות יוצאות; ל-uChat אין לנו כזה כרגע.

### 4. תקלת LLM (§5)
כשה-LLM מחזיר את טקסט השגיאה הגנרי, ההודעה הנוכחית לא נספרת כ"תסכול" באותו תור. "?" בודד בזמן תקלת API כבר לא מסלים לקורלי מיד; הסלמה רק אחרי שני תורים אמיתיים.

### 5. הקשר ל-LLM (`llm-fallback.ts`, דפוס Edry Connect)
שורת הקשר לפני כל תור: באמצע מסלול "ההורה כנראה ענה משהו שהתהליך לא הבין או סטה; ענה לו כבן אדם ואז הזכר במשפט אחד את השאלה הפתוחה מההודעה הקודמת שלך; אל תתחיל תהליך ואל תמציא אפשרויות". אחרי הפניה: "ענה קצר וחם, אל תבקש פרטים, אל תבטיח פעולות". מפתחות פנימיים (`__miss`, `__handoff_llm`) לא נחשפים לפרומפט.

### 6. תוספת באותו יום (2.4.1, `faf130f`): שם ילד ופרידה/דחייה
- **שם ילד לא נבלע:** `childNameGuard` משותף ל-4 שלבי שם-ילד (`register_complete_placeholder`, `payment_setup_child_name`, `payment_fail_child_name`, `handlePaymentStatusChildName`) על בסיס `looksLikeChildName` הקיים: שאלה/משפט/מילת-מטא → LLM; לא נראה כמו שם → הבהרה `notUnderstood` (נכנס לסולם).
