## המסווג העמיד (`offerVerdict`)
- **אוצר-אישור סגור** (`AFFIRM_VOCAB`): `accept` רק אם **כל** מילות ההודעה שייכות לאוצר. צירוף חופשי ("כן בטח", "בוא נעשה הוראת קבע") מתקבל; מילה זרה אחת ("רוצה *לחשוב*", "כן *בהמשך*", "אני *צריך*") שוברת → הבהרה. **לא** regex תחילת-משפט ולא הגבלת אורך. ברירת המחדל הבטוחה: לא-לאשר.
- **סדר קדימות:** שאלה/בקשת-הסבר (`EXPLAIN_RE`+`isRealQuestion`) → דחייה/היסוס (`DEFER_RE`: "לא עכשיו"/"נראה"/"תלוי") → סירוב (`REFUSE_RE`/שלילה/שיטה) → אישור → עמום.

## הקורפוס הממצה (88 מקרים) — ומה הוא חשף
בדיקת `replay` כוללת עכשיו טבלה מקוטלגת: **accept / question / refuse / unclear** — כל קטגוריה עם עשרות ניסוחים והתוצאה הצפויה. הקורפוס חשף 3 באגים אמיתיים שתוקנו:
1. **"לא רוצה" בשלב ההצעה נותב ל־`cancel_child`** (מסלול ביטול) — בדיוק ה"בלבול" שהלקוח דיווח: הורה שאומר "לא רוצה [הו"ק]" נשאל "איזה ילד לבטל?". **תוקן:** `ביטול` נוסף ל-`STEP_OWN_INTENTS` של `payment_setup_offer` → נשאר בהצעה → `offerVerdict` → refuse → תפריט חלופות.
2. **"סגור"** — מילה שמורה (יציאה) שה-handler חוטף; הוסרה מאוצר-האישור.
3. **"תפריט"** — מילה שמורה (תפריט ראשי); הוסרה מקורפוס הסירוב (התנהגותה נכונה בפני עצמה).
